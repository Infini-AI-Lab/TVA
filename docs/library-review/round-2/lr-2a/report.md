## New issues

- **NEW** soundness — `tvr check` trusts that a kernel's Lean was kernel-checked, but nothing enforces it: a kernel `.lean` file can add `main`/`consistent` to the environment through meta-programming (`run_cmd`/`#eval`/`elab`/`macro` calling `Environment.addDeclCore … (doCheck := false)` or `addDeclWithoutChecking`), so the proof term is never verified. `work/lean/GateHygiene.lean` is such a bundle with `Post = False`: `lake env lean` exits 0 (`build`), the shape `example`s elaborate (`shape`), `#print axioms main` is `[propext]` (`axioms`), `main` uses its projection (`usage`), and tvr's `hygiene` regex finds nothing (`work/hygiene_regex.out`). The hygiene denylist blocks `native_decide` and `set_option debug.*` but not this route. Where: `tools/tvr.py` `check` (`hygiene`) and `tools/claim_reader.lean.in` (`axioms`). Fix: forbid meta-level env mutation in kernel Lean files (`run_cmd`, `#eval`, `elab`/`elab_rules`, `macro`/`macro_rules`, `initialize`, `addDecl*`, `doCheck`, `skipKernelTC`, `ofReduceBool`/`ofReduceNat`), or re-verify the kernel's oleans with an external kernel checker (`leanchecker`/replay) instead of trusting the elaboration environment.
- **NEW** soundness — `docs/TRANSCRIPTION.md` §10's "pure expression" is unsound for aggregate operands. It lists `+`, `-`, `*`, the comparisons and `is`/`is not` as pure with "no call of any kind" that "a reviewer checks by reading the expression". But on a `triton.language.core._aggregate` value these operators dispatch to the value's `@triton.jit` dunder methods (`code-generator.py:795-808`, `visit_Compare` `:1076-1091`), which are inlined and may run atomics. `work/l6_operator_dispatch.py` (H200): `(a+a) is not None`, `a == a`, `a < a` and a `dead` `a+a` each run the operator's atomic in all 4 programs, yet each would be dropped as `compile-check`/`no-op:print`/`dead`. The hole affects all three drops. Fix: restrict purity to operands of constexpr/dtype/shape/tuple/plain-scalar type (exclude aggregates and overloaded operators), or exclude aggregate operands in `exclusions.md`.
- **NEW** soundness — the independence path check misses the `$HOME` and `file://` spellings, so a file can name a path into a sibling project under the home directory and pass `tvr audit` and the gate's `independence` check, although §2 promises to flag "a home path other than TVA". `work/l7_path_forms.py` (against the tool's own `foreign_refs`): a `~`-prefixed home path and a `/home`-prefixed absolute path to such a sibling are flagged, but the same location written with `$HOME`, `${HOME}` or a `file://` URL is not (`_ABS` matches only tokens that start with `~` or `/`; `_REL` skips tokens with no `..`). Where: `tools/tvr.py` `_ABS`, `_REL`, `foreign_refs`. Fix: recognise `$HOME`/`${HOME}` as the home prefix and strip a `file://` scheme before the path test.
