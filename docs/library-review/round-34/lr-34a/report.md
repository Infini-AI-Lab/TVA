## New issues

- **NEW** soundness — `Step.defer` (`lean/TVA/Sem/Step.lean`) lets a pending atomic be passed only by a later step that is the same for every old value. A tensor `store` or `load` is one step, so a store that uses any lane of an atomic's result holds back every later atomic of the program. On the device, each thread orders only its own accesses. `work/crosswarp_nowait.py` is a well-behaved launch: shared cells are reached only by `acq_rel` gpu atomics, there is no `IntraRace`, and no program waits. Program 0 runs `r = tl.atomic_add(Y + x, 0)`, `tl.store(OUT + x, r)`, `tl.atomic_add(C + x, 1)` (`acq_rel`, or unused `relaxed`). Program 1 runs `q = tl.atomic_add(C + 511, 0)`, `tl.atomic_add(Y, q)`. The semantics gives no outcome with `Q = 1` and `OUT[0] = 1`. The H200 gave it in 200/200 launches for each `sem`, because warp 3 wrote `C[511]` before warp 0 read `Y[0]`. So `Compiler.Faithful` is false for this launch. `Event.Strong`'s "the interleaving semantics is exact", SEMANTICS.md "Atomics" ("in any order their dependences allow") and `MemSem.unused`'s premise are all wrong. Fix options: (1) per-lane steps for stores and loads that can be deferred while they depend on a pending atomic; (2) exclude, or make not well behaved, launches that use an atomic's result on a cell another program also accesses. No claim uses one today.
- **NEW** wording — SEMANTICS.md "Atomics" and `lean/TVA/Lang/Ops.lean:365-374` define "unused" on the source and on the IR without saying which governs. They differ for a value read only by a pure operation that is itself unused (`s = r + 1` with `s` never read, `tl.device_assert(r > 0)` without `debug`), and for a value returned from a helper whose call is a statement. Fix: say that either reading is sound, and that the model drops the value only if nothing that runs on the device reads it.
