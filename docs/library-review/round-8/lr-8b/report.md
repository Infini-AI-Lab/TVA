## Verdicts

- **L1** ACCEPT — "Which value" is what 3.8.0 does: `_find_carries` dry-visits a loop body with every name bound to its value before the loop and the induction variable bound to a `ub.poison` placeholder that is replaced and left dead (`code-generator.py:465-503, 1276-1326`); `set_attr` marks the defining operation, and on a block argument leaves only `tt.divisibility_arg<N>` on the loop (`ir.cc:411-425`), which AxisInfo never reads (it reads hints only in `visitOperation` and `getPessimisticValueState`, `AxisInfo.cpp:1234-1259, 1318-1340`; the `_arg` suffix is the only such string in `libtriton.so`). Re-ran evidence/hint-loops: 13 of 13 cases as recorded. The transcription row, the pitfall and `no-op:hint` agree with it, and tutorial 06's hint on `start_n` is correctly a hint with no effect. One defect of the same section predates L1 and is filed under New issues (a hint on one result of an operation with several results).
- **L2** ACCEPT — The reading is sound, and it is no stronger than what Triton promises: the 3.8.0 docstring (`core.py:3307-3330`) defines `multiple_of` by "the first element of every contiguous group", every element at contiguity 1, and the compiler's own belief is the same, with the dimension of contiguity 1 applied to every dimension (`AxisInfo.h:31-40, 92-101`). Re-ran evidence/hint-rank2 (15 of 15 as recorded); C1 shows "groups of `C`" alone is unsound, and my `work/t_hint_global.py` shows the "fastest dimension only" reading is unsound too: `tl.multiple_of(p, [16, 1])`, which says nothing about the fastest dimension under that reading, made the loads with 72-byte rows `ld.global.v4.b32`, and they faulted. On the coordinator's question: the reading is stronger than what 3.8.0 *relies on* in tutorials 08 and 09. Tutorial 08 uses only the row starts (R1 correct, R2 faults). In tutorial 09 the wrongly read lanes land in columns the store masks off. But both are facts about which compiler consumer reads which part of the belief: a reviewer cannot check them from the values, and C1 and `t_hint_global` show they are false in general. So a sound reading lets tutorial 09 claim full tiles only: `M` and `N` multiples of `BLOCK_SIZE_M` and `BLOCK_SIZE_N` for every config the autotuner may pick. Tutorial 08's pointer kernel has no launch on which its hint holds, by Triton's documentation as well (see L37). One minor point: with both hints on one value, `ContigIs`'s "not groups of `2·C`" is stronger than needed, because the pair replaces the compiler's whole belief. It is harmless for the tutorials, whose `C` is the dimension.

## New issues

- **NEW** soundness — A name assigned a Python number holds a tensor, which SEMANTICS.md never says. `visit_Assign`'s `_sanitize_value` (`code-generator.py:727-750`) turns a Python number assigned to a name into a scalar tensor of its own dtype (`to_tensor`, `Operand.ownType?`), unless the target is annotated `: tl.constexpr`. This covers a literal, the value of a `tl.constexpr`, and each element of a tuple. A literal passed directly to a helper stays a compile-time value there (`call_JitFunction`, `normalize_value`, `:1358-1365`). SEMANTICS's rules for Python numbers ("Constants", "Operators and promotion") and for compile-time values ("Order", the compile-time `if`), and TRANSCRIPTION's rows and drops built on them, read as if `s = 0.5`, `F = False` or `a = -7` still held Python values. On the device (`work/t_assign_literal.out`), a model that follows those rules differs from the source. `e = 1e-7; y = x * e` with a `bfloat16` `x` gives `1e-7·x` in `float32`, while the literal in place gives `0`. `s = 0.5; x * s` is `float32`, not `bfloat16`. After `F = False`, `if F and tl.atomic_add(c, 1) > 0:` ran the atomic in 64 of 64 programs (0 with the literal in place), and `if F: tl.static_assert(False)` is visited and rejects the kernel. `a = -7; b = 2; a // b` stores `-3` (truncation), where the literal in place gives Python's `-4`. Tutorials 05 (`mean = 0`), 06 (`lo, hi = 0, …`, `start_m = 0`, `start_n = 0`), 08 (`last_problem_end = 0`) and 10 (`offs_k_a = 0`, carried by the loop) rely on this. Fix: state it in SEMANTICS "How the front end evaluates the source", in the `Operand` docstring of `TVA.Lang.Promote` and in "Constants", and add a TRANSCRIPTION pitfall.
- **NEW** soundness — A hint on one result of an operation with several results is a hint on every result. `tt.split` has no AxisInfo visitor, so `visitOperation` gives each result its `getPessimisticValueState`, which reads the hint off the defining operation (`AxisInfo.cpp:1234-1259, 1318-1340`). The same holds for a `tl.reduce` or `tl.associative_scan` of a tuple, `tl.max`/`tl.min` with `return_indices`, and a helper Triton does not inline that returns a tuple, by the same code; only `tt.split` was tested. On the device (`work/t_hint_multiresult.out`): with `a, b = tl.split(z)`, where `a = 4i` and `b = 4i + 2`, the true hint `a = tl.multiple_of(a, 4)` made the load through `b` `ld.global.v4.b32`, and it faulted with a misaligned address; without the hint the loads are scalar and correct. The model the library prescribes (a check on `a` where it is defined: SEMANTICS "Which value", TRANSCRIPTION row 80) is well behaved, so `Faithful` is false for it. Fix: in SEMANTICS "Compiler hints" and the `TVA.Lang.Ops` hint section, say that a hint on a result of an operation with several results promises the same about each result (the model checks each one), or exclude such hints. No pinned tutorial hints such a value.
- **NEW** wording — Four items: (a) SEMANTICS "One launch" and `Faithful`'s "Which launch" speak only of memory, but hooks also change the launch's arguments: tutorials 06 and 09 set a host `TensorDescriptor`'s `block_shape` in a config's `pre_hook`. Say that the claimed launch has the arguments as the last hook leaves them. (b) SEMANTICS "A runtime `if`": "otherwise the kernel is rejected on the host" reads as if a name defined in one branch only were rejected. It is rejected only if used after the `if` (R5). (c) SEMANTICS "Index arithmetic": "below `2^31` in magnitude" leaves out `-2^31`, which is `int32` ("Scalar arguments" says `[-2^31, 2^31)`). (d) TRANSCRIPTION "Masked-off lanes": "gives unspecified values, never `0`" reads as "is never 0". Say "not necessarily `0`".
