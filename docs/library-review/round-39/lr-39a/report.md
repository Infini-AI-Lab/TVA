## New issues

- **NEW** gap — `Tile2.safe_load_tile2`, `safe_store_tile2`, `Buf.tile2_sub_bytes` and `Buf.tile2_disjoint_of` (`lean/TVA/Lemmas/Tile2.lean`) require `e + (M - 1) * s0 + (N - 1) * s1 < b.len` even when the tile has no element. An empty matrix that starts at the end of its buffer (`M = 0`, `e = b.len`: the last sequence of a varlen batch, of length 0, with every lane masked off) is then out of their reach, although the access is safe. `work/tile2_empty.lean` proves that load safe through `safe_load_buf` and `addrs_tile2` and shows the premise false. The 1-D `safe_load_block` takes `n ≤ b.len`, which admits `n = 0`. Fix: take `M = 0 ∨ N = 0 ∨ e + (M - 1) * s0 + (N - 1) * s1 < b.len`, or `∀ x, Elem e s0 s1 r0 c0 BM BN M N x → x < b.len`.
- **NEW** wording — `Recurrence.exp_sub_mem_Ioc`'s docstring (`lean/TVA/Lemmas/Recurrence.lean`) says a kernel uses it "for the `|g t| ≤ 1` of `perturb_le_sum`". But `perturb_le_sum` bounds the computed decay `|ĝ t|`, a float's value that an approximate `exp` may round above `1` (the reason for `perturb_le_pow`), not the exact `Real.exp` this lemma bounds. Fix: point to `perturb'` (which bounds the exact gate, `|g t| ≤ G t`) with `run_le_sum`, and to `abs_le_sum`.
- **NEW** wording — `Tile2.start_arange64_toInt`'s docstring (`lean/TVA/Lemmas/Tile2.lean`) gives `pid.to(tl.int64) * BM + tl.arange(0, BM)` as the form it states, with "the `int32` `arange` cast to `int64`" (`castInt`). SEMANTICS.md and TRANSCRIPTION.md model that implicit promotion as `tl.convert .i32 .i64` (a `ConvRel` pick, `safe_convert`), so a faithful transcription never reaches the lemma's form. Fix: state it for the result of `tl.convert` (lanes related by `ConvRel P .i32 .i64`), or say to combine `ConvRel.toInt_i32_i64` with `start_add_toInt`. In the same file, `Tile2.toInt_mul_nat`, `toInt_add_nat`, `toInt_mul_ofNat` and `arange_toInt` repeat `IntV.mul_nat`, `add_nat`, `mul_ofNat` and `IntV.I32.toInt_tl_arange` of the same batch, with an extra `0 < w` premise. Keep one of each.
