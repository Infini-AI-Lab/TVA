## New issues

- **NEW** gap — The offset and pointer lemmas of `TVA.Lemmas.Tile2` (`off_toInt`, `ptr_lane`, `ptr_lane_seq`, `ptr_lane_sum_of`) need the largest offset over every lane, masked-off ones included: `(r0 + BM − 1)·s0 + (c0 + BN − 1)·s1 < 2^(w−1)`. Their consumers (`addrs_tile2`, `accBytes_tile2`, `safe_load_tile2`, `safe_store_tile2`) take `hp` for all lanes `(i, j)`, enabled or not. In the model a masked-off lane's wrapped offset is never used (`tl.addrs` gives it no address), so the bound is stronger than needed. A claim whose condition bounds only the matrix, `(M−1)·s0 + (N−1)·s1 < 2^31`, cannot use these lemmas for the last partial tile: with `M = 1000`, `BM = 64`, `s0 = 2149000`, the matrix bound holds but `1023·s0 > 2^31`. `TVA.Lemmas.Block`'s `Fits p B` has the same limit for the 1-D block. Fix: let `addrs_tile2` and the load/store rules take `hp` for enabled lanes only (`r0 + i < M → c0 + j < N → …`), and add lane lemmas for enabled lanes from `(M−1)·s0 + (N−1)·s1 < 2^(w−1)`, with the same for `Block`.
