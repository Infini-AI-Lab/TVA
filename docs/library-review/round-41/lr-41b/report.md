## New issues

- **NEW** gap — No check makes sure the fixed claims still elaborate. Round 39's `simp` lemmas broke `claims/layer_norm_fwd_f16/Claim.lean` (L189), and two review rounds missed it: `tools/tvr.py` never reads `claims/`, and neither `tvr release` nor `tvr library-check` elaborates a `Claim.lean`. The user requires that "we should keep the 41 claims unaffected", and `claims/README.md` lists "It builds" as a check, but nothing enforces either. The release check could close this. Each claim imports only `TVA` and Mathlib, so the release check can run `lake env lean claims/<k>/Claim.lean` for every claim in its sandbox after `build`, and fail on any error. This would check only that each claim elaborates, not any proof, so it keeps "checks no claim" (L160). The library reviewers' checklist in LIBRARY_REVIEW.md should say the same.
- **NEW** gap — L184 generalised the strided terms but not the unit-stride ones. `Tile2.col_toInt` and `row_toInt` (`rows[:, None]`, `cols[None, :]` with no stride) still take only `r0 + i` and `c0 + j` lanes. Yet `add_toInt_on`'s docstring offers `fun i j _ => col_toInt hr i j` as the row term for enabled lanes. For `% N` columns used without a stride, as in `x_ptr + rows[:, None] * s + (offs % N)[None, :]`, `row_toInt` does not apply, and the prover must re-derive it (`work/UnitStride.lean`: U1 fails, U2 is the hand proof). Fix: state `col_toInt` and `row_toInt` (or `…_on` forms) for any `ρ` and `κ`, as the twelve `…_on` lemmas now are.
- **NEW** wording — The example in `lean/TVA/Lemmas/IntW.lean`'s section docstring "The integer cast (library issue L185)", `safe_convert_iff (fun i r => ConvRel.iff_cast_i32_i64) (y := x.castInt)`, does not elaborate. `(y := x.castInt)` is elaborated against `Tensor s ?d'.Val` before `d'` is known, so Lean reports a type mismatch at any shape (`work/Variant.lean`, `work/variant.out`, V1 and V3). The form `safe_convert_iff fun _ _ => ConvRel.iff_cast_i32_i64` works, with `y` taken from the goal (V2, and the author's probe). Fix: write that form in the docstring.
