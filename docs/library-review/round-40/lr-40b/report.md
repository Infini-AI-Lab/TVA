## New issues

- **NEW** gap — The release check's `audit` step can no longer pass. The commit after round 40 that stops tracking `kernels/` made `cited_files` in `tools/tvr.py` call `shipped_files()` unconditionally. That runs `git ls-files` on the TVA root, but the release copy has no `.git` (the audit's own comment says "a release copy has no git metadata"). So `tvr audit` in the sandbox dies with `git ls-files failed: … not a git repository`. I reproduced this on a copy of the shipped files with no `.git` (Re-ran). The release run fails there too, and fails earlier: inside the sandbox `system_tool("git")` refuses `/usr/bin/git` (the sandbox shows root's files under another owner id), so `audit` stops with `git ls-files failed: /usr/bin/git is not the system's git`. Fix: when there is no `.git`, read every Markdown and Lean file, because the copy holds only what ships. That is the guard `main` already uses for `shipped_problems`.
- **NEW** gap — The shipped TVA fails its own audit, and the local audit cannot see it. `lean/lakefile.toml` still lists 37 kernel `lean_lib`s (`srcDir = "../kernels/<k>/lean"`), and `lake_violations` refuses a `lean_lib` with no kernel folder. `README.md` and `docs/LIBRARY.md` link to `kernels/README.md`, which no longer ships. `tvr audit` in a fresh git copy of the shipped files reports 39 problems: 37 `lean_lib`s and the 2 citations. In the working tree it prints `independent`, because `citation_problems` checks a target against the local tree, where the git-ignored `kernels/` still exists, and not against what ships. Fix: remove the kernel `lean_lib`s (and `add_lake_lib` with `tvr new`, or keep them out of the shipped lakefile), point the two links elsewhere, and have `citation_problems` require a cited TVA file to be shipped (in a git checkout).
- **NEW** wording — Several documents still describe `kernels/` as shipped and read by the release check. These are REVIEW_PROTOCOL.md §2 ("Of `kernels/` the check still reads each kernel's review records … and the text and imports of every file", "Every file under `kernels/` is scanned"), LIBRARY_REVIEW.md's `gate` row, LIBRARY.md ("Build: … targets `TVA` and one library per kernel folder", and the "Kernels" section with "Twelve kernels"), and README.md ("Kernels: …"). After the commit that stops tracking `kernels/`, the release check reads nothing of `kernels/` (the copy has none), `lake build` builds `TVA` alone, and `kernels/` ships with nothing. Fix: say that `kernels/` is local and not shipped, and that the release check covers no kernel.
