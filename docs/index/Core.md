### `TVA.DotCfg.precision`

```lean

```

The source's `input_precision`. When the source omits it, Triton uses
`triton.knobs.language.fp32_default` if set, and otherwise `tf32` on sm_90 (`ieee` with

### `TVA.MemSem.unused`

def · [lean/TVA/Program.lean:72](../../lean/TVA/Program.lean#L72)

```lean
TVA.MemSem.unused (sem : TVA.MemSem) : TVA.Scope → TVA.MemSem
```

**The order of an atomic whose result is unused**: `acq_rel` at `gpu` or `sys` scope,
whatever the source's `sem`; the source's `sem` at `cta` scope. The model of a `tl.atomic_*` whose
returned value the source never uses gives its read-modify-writes this order (`TVA.Triton.Memory`),
so that two of them, or one and an `acq_rel` atomic, on the same bytes from different programs do
not race (`TVA.Launch`).

Why this is sound. In TVA's semantics an atomic's `sem` decides nothing but whether a pair of
atomics races; atomics create no synchronisation between programs. What a weaker order
(`relaxed`, `acquire`, `release`) adds on the device is that the atomic may be performed out of
order with its thread's other accesses. *Later* is already allowed: the semantics performs an
atomic after later steps that do not depend on its result. *Earlier* cannot be observed:

* within the program, since its result is unused, no step depends on when it was performed;
* through the atomic's own bytes, since in a well-behaved launch only atomics access them (a plain
  load or store of them would race with the atomic, or conflict within its program), and
  atomics on one cell are performed with single-copy atomicity (PTX ISA §8.10.3; a `.relaxed`
  `atom` or `red` is a strong operation, §8.4), so each update is one step in the cell's order
  of updates, as in an interleaving;
* through other bytes the program accessed, since another program accessing them would race.

At `cta` scope the atomic is not ordered with respect to other programs' accesses at all, so the
source's `sem` is kept and the race rule applies to it unchanged.

### `TVA.Tensor.permute`

def · [lean/TVA/Tensor/Layout.lean:137](../../lean/TVA/Tensor/Layout.lean#L137)

```lean
TVA.Tensor.permute {s : TVA.Shape} {α : Type} (x : TVA.Tensor s α) (dims : List ℕ)
  (h : dims.Perm (List.range (List.length s)) := by (try simp only [List.length_cons, List.length_nil]); decide) :
  TVA.Tensor (List.map s.dim dims) α
```

`tl.permute(x, dims)`, and `tl.trans(x, dims)`: the result has shape
`[s[dims[0]], s[dims[1]], …]`, and its element at `o` is the element of `x` whose coordinate
`dims[k]` is `o.coord k`, for every `k` (`get_permute`). `dims` must be a permutation of
`0, …, rank − 1` (Triton rejects any other list at compile time); for a shape of literal rank the
default proof `h` is found by itself.

* A rank-2 `tl.trans(x)` or `x.T` is `Tensor.trans`, which equals `x.permute [1, 0]`
  (`permute_trans`).
* `tl.trans(x)` with no `dims` on a tensor of rank `r ≥ 3` swaps the last two axes
  (`core.py:2091-2097`): the model writes `dims` as a literal list (`x.permute [0, 2, 1]` for
  rank 3), so that the result's shape reduces to the source's.

### `TVA.Tensor.broadcastTo`

def · [lean/TVA/Tensor/Layout.lean:235](../../lean/TVA/Tensor/Layout.lean#L235)

```lean
TVA.Tensor.broadcastTo {s : TVA.Shape} {α : Type} (x : TVA.Tensor s α) (t : TVA.Shape)
  (h : s.bcastOk t = true := by decide) : TVA.Tensor t α
```

`tl.broadcast_to(x, t)`, and the method forms `x.broadcast_to(t)`, `x.broadcast_to(*t)`
(`core.py:2049-2066`, `semantic.py:711-725`), of a block `x` of shape `s`: the block of shape `t`
whose element at `o` is `x`'s element at `o`'s coordinates, except that each dimension of size
`1` in `s` is read at `0` (`get_broadcastTo`). Triton accepts only a `t` of the same rank whose
every dimension equals `s`'s or where `s` has `1` (`Shape.bcastOk`, the proof `h`; for shapes of
literal sizes the default proof is found by itself). A scalar's broadcast is `Tensor.full`
(`semantic.py:629-634`). `col`, `row`, `bcastCols` and `bcastRows` are special cases.
