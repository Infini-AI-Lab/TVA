### `TVA.AddRel`

def · [lean/TVA/Triton/Arith.lean:56](../../lean/TVA/Triton/Arith.lean#L56)

```lean
TVA.AddRel {f : TVA.Format} (fusion : Bool) (x y r : TVA.FloatV f) : Prop
```

The results an addition `x + y` may produce when either operand may be a product.

Without fusion, the IEEE sum up to NaN payload. With fusion, also what an `fma` gives: an `fma`
takes one product unrounded and its other operand as it is (sm_90 has no instruction that adds two
unrounded products). The model does not track which operand is the product, so this allows:
- the rounding of `p + q` for exact `p`, `q` that round to the operands (`RoundsTo`), one of them
  the operand's own value (`p = x.toRat` or `q = y.toRat`), with either sign for an exact zero;
- an infinite operand added to an exact other operand, which gives that infinity.

### `TVA.computationType?`

def · [lean/TVA/Triton/Promote.lean:188](../../lean/TVA/Triton/Promote.lean#L188)

```lean
TVA.computationType? (a : TVA.DType) (aPy : Bool) (b : TVA.DType) (bPy divMod : Bool) : Option TVA.DType
```

`computation_type_impl` (`semantic.py:68-116`): the dtype a binary operator computes in, from
its operands' dtypes (a Python number's own dtype) and which of them are Python numbers; `divMod`
for `/`, `//` and `%`. The first that applies:
0. one operand a Python number of a kind no higher than the tensor's (`DType.kind`): the tensor's
   dtype (`float32` for `float16`/`bfloat16` under `divMod`);
1. either `float64`: `float64`; 2. either `float32`: `float32`;

5. two fp8: the same one, or `float16` for two different ones;
6. otherwise both must be integers (an fp8 with an integer is rejected), not of mixed signedness
   under `divMod`, and the result is `intPromote`.

### `TVA.BinOp.typing?`

def · [lean/TVA/Triton/Promote.lean:262](../../lean/TVA/Triton/Promote.lean#L262)

```lean

```

How the front end types `x op y` when at least one operand is a tensor (`none`: rejected on
the host).
* `+ - *`: `common?`; the result is that dtype.
* `/` (`semantic.py:292-315`): `common?` with `divMod`; two integers are both converted to
  `float32` (`int64` included).
* `//`: `common?` with `divMod`, integers only. `%`: `common?` with `divMod` (a float `%` is
  `frem`, which TVA does not model).
* `& | ^ << >>`: `common?`, integers only.
* comparisons: each Python number first becomes a tensor of its own dtype, then `common?`; the
  result is `int1`. So `x < 2**31` with an `int32` `x` compares in `uint32`.
* `tl.minimum`, `tl.maximum`: the same own-dtype step, then `bfloat16` becomes `float32`, then
  `common?`.

### `TVA.tl.sort`

def · [lean/TVA/Triton/Scan.lean:113](../../lean/TVA/Triton/Scan.lean#L113)

```lean
TVA.tl.sort {s : TVA.Shape} {α : Type} [TVA.SortKey α] (x : TVA.Tensor s α) (descending : Bool := false) :
  TVA.Prog (TVA.Tensor s α)
```

`tl.sort(x, descending=…)` along the last dimension: each row without NaN comes out as a
permutation of itself (up to `==`), sorted; a row with a NaN is unconstrained.
