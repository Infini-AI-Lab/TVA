TVA: AI Agents Prove Triton Kernels Correct

TVA is a Lean 4 library for proving Triton kernels correct. AI agents write the proofs in a sandbox, and Lean checks them. On every covered launch, a proved kernel never faults, races or writes outside its outputs, and each output is within a stated bound of the exact result.

Zhuoming Chen · InfiniAI Lab, Carnegie Mellon University · November 2026
Code on GitHub ↗

The inference stack is under attack

  • Fireworks AI: internal credentials misused in October 2026, then a breach through a cloud provider that exposed some customers' secrets, datasets and partial model weights (Crypto Briefing, Dr. Web).
  • SGLang: CVE-2026-5760 (CVSS 9.8), a chat template in a GGUF file that runs code on the server (The Hacker News, CSA).
  • PHP packages: backdoored releases of intercom-php and Laravel-Lang (Cloudsmith, The Hacker News).

None of these touched a GPU kernel, but kernels are the kind of code attackers target: trusted, fast-changing, and too large to re-read. vLLM and SGLang hold about 1,800 Triton kernels, and agents now write many new ones. A kernel can access all GPU memory, including every request's KV cache, and its bugs are silent: a wrapping int32 offset, an off-by-one mask or a race returns a plausible wrong answer. Researchers have already built backdoors triggered by compiler optimizations or hardware (1, 2).

Tests sample shapes; a proof covers every launch. Proofs cost too much to write by hand, so we let agents write them.

What TVA is

  1. A Lean 4 semantics of Triton (8,300 lines): tensors, tl.* operations, masked memory access, atomics, and launches as interleaved programs over byte memory. Floats are exact IEEE formats, fp32 down to mxfp8; integers wrap. Hardware-dependent results (tl.exp, tl.dot accumulation order, float atomics) range over what device facts allow, each measured on an H200.
  2. A proof kit (16,000 lines of proved lemmas): access patterns, loops, integer widths, float error, tl.dot accumulation, online softmax, recurrences, scans and atomics.
  3. A sandbox: a container with the library, its docs and a grader.

Stating a claim

A claim transcribes a kernel line by line, states the covered launches (ok) and the required final memory (Post), and is pinned by its SHA-256: 

def Claim.Holds (c : Claim) : Prop :=
  ∀ P, Device P →                    -- every platform with the H200's device facts
  ∀ d, c.ok d →                      -- every covered launch: shapes stay symbolic
  ∀ init, c.Pre d init →             -- every initial memory, including the data
    Correct (c.kernel d) (c.launch d) init (c.Post d init)
-- Correct: no undefined behaviour, no race between programs, and every way the launch can end
-- is a normal end (no fault, no hang) whose final memory satisfies Post.

Vector addition from the Triton tutorial:

def add_kernel (x_ptr y_ptr output_ptr : Ptr .f32) (n_elements : I32) (BLOCK_SIZE : Nat) : Kernel where
  body ctx := do
    let pid := tl.program_id ctx 0
    -- `pid * BLOCK_SIZE` is computed in int32, and wraps
    let block_start := pid * (IntV.ofNat BLOCK_SIZE : I32)
    let offsets := block_start + tl.arange 0 BLOCK_SIZE
    let mask := offsets.ltS n_elements
    let x ← tl.load (x_ptr + offsets) (some mask)
    let y ← tl.load (y_ptr + offsets) (some mask)
    let output ← tl.add x y
    tl.store (output_ptr + offsets) output (some mask)

Its Post: output j is the IEEE sum of inputs j, and every other byte is unchanged. Every claim includes that last clause.

Production kernels need explicit conditions. SGLang's 50-line embedding lookup needs eleven, none stated in its source, for example: BLOCK_H is a power of two, the int32 column index cannot wrap, and the output does not alias the inputs. For float outputs, Post bounds the error against the exact result, with tolerances derived from the device facts.

What you trust

Lean and Mathlib; the transcription; Triton 3.8.0 compiling as modeled, outside 56 listed exclusions; and the measured device facts. Lean checks the rest, including every agent-written proof.

Agents prove, a machine grades

The agent receives one claim as a Harbor task, with the library, docs and one worked example, and writes theorem main : claim.Holds. A separate grader checks that:

  1. the claim file matches its pinned hash;
  2. the proof has no sorry, axiom, native_decide, meta code or other escape hatch;
  3. everything builds from scratch;
  4. main has type claim.Holds and uses only the standard axioms;
  5. Lean's kernel re-checks every declaration.

The reward is 1 or 0. Agents never see reference proofs: a task holds only the claim's files, and the container's only network route is the model endpoint.

Results: agents proved all 41 claims

We wrote fixed claims for 41 kernels with TVA: 14 Triton tutorial and library kernels (fp16, fp8 and mxfp8 GEMMs, stream-K, FlashAttention forward and backward, paged attention, …) and 27 production kernels from SGLang (12), vLLM (7) and flash-linear-attention (8), including paged and varlen attention, fused MoE, LoRA, int8 GEMM, rejection sampling, and Mamba-2 and gated DeltaNet recurrences.

Claude Sonnet 5.5 agents proved 40 of them; the 41st is the vector-addition example. Every proof passes the grader in a fresh container.

Volta proves equivalence to a reference with static sizes, pointers and branches, over the reals; its open implementation, ptx_verifier, emits Lean propositions. SentryWard verifies warp-specialized Hopper and Blackwell kernels at fixed sizes, without data-dependent addresses. Formalizing PTX in Lean covers the full PTX memory model for hand-written PTX. GPUVerify and Faial prove race freedom only; ProofWright and Browne et al. handle elementwise kernels or a CUDA subset.

TVA trades PTX-level depth for coverage. It trusts the Triton compiler and handles run-time shapes, data-dependent addresses, wrapping integers and bounded float error, which real-number proofs cannot express.

Limits

  • TVA trusts Triton 3.8.0, minus the listed exclusions, and targets the H200.
  • Claims are hand-written; readers must check each transcription.
  • A proof guarantees only its claim; each claim lists the launches it excludes.
  • Proofs are long, and agent time costs money.

What's next

The 41 claims form a benchmark scored by a machine check that weakening the specification cannot game. Next, we want agents to answer a buggy kernel with a launch that breaks it. Code: github.com/Infini-AI-Lab/TVA.
