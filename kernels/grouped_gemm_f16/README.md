The kernel computes `G` independent products `C_g = A_g · B_g` in `float16` with `float32`
accumulation. Program `p` takes the global tiles `p, p + NUM_SM, p + 2·NUM_SM, …`, where the tiles
are numbered problem by problem, row-major within a problem.

## Specification

`Post d init fin`, for every problem `g < G` and every element `(i, j)` of `C_g`:

- there is a finite `float32` value `o` such that `C_g[i, j]` in final memory is `o` rounded to
  `float16` (to nearest even, up to NaN payload);
- `|o − Σ_{k<K} A[i,k]·B[k,j]| ≤ errC(K, S)`, with `S = Σ_{k<K} |A[i,k]·B[k,j]|` and the entries
  read from initial memory;
- every byte outside the `C` buffers is unchanged.

The bound is

```
errC(K, S) = ((1 + ρ)^T − 1)·S + T·(1 + ρ)^T·α        with T = K / BK,
ρ = rel(BK) + 3u·(1 + rel(BK)),   α = abs(BK)·(1 + 3u) + 4η,
rel(K) = (K + 2)·2^-22,   abs(K) = (K + 2)·2^-126,   u = 2^-24, η = 2^-150 (float32).
```

`errC_le` gives the closed form `errC(K, S) ≤ 2T·(ρ·S + α)`.

| `BK` | `K` | `T` | `ρ` | `errC / S` | closed form `/ S` |
|---|---|---|---|---|---|
| 32 | 1024 | 32 | 8.29e-6 | 2.65e-4 | 5.30e-4 |
| 32 | 4096 | 128 | 8.29e-6 | 1.06e-3 | 2.12e-3 |
| 64 | 4096 | 64 | 1.59e-5 | 1.02e-3 | 2.04e-3 |
| 128 | 4096 | 32 | 3.12e-5 | 9.98e-4 | 2.00e-3 |
| 64 | 16384 | 256 | 1.59e-5 | 4.08e-3 | 8.15e-3 |

The absolute part `T·(1+ρ)^T·α` is below `2^-90` in every row. The bound is about
`K · 2.4·10^-7 · S`. It is a worst case under the assumed tensor-core accuracy, not a typical
error.

## Conditions

`Gemm.ok`, for each problem (`A` is `M × K`, `B` is `K × N`, `C` is `M × N`, all `float16`, row-major
with leading dimensions `lda`, `ldb`, `ldc` in elements):

- **shapes**: the buffers have `M·lda`, `K·ldb` and `M·ldc` elements, and `K ≤ lda`,
  `N ≤ ldb`, `N ≤ ldc`;
- **full tiles**: `BM ∣ M`, `BN ∣ N`, `BK ∣ K`. The kernel has no masks ("assume full tile for
  now"), so on other sizes it reads and writes out of bounds;
- **`int32`**: the sizes and leading dimensions are below `2^31`, and so are
  `M + BM`, `N + BN`, `K + BK` (`cdiv`), `M·lda`, `BK·ldb` and `M·ldc` (the `int32` offsets);
- **accumulation range**: `(K/BK)·ρ ≤ 1/2`. This allows `K` up to about `1.9·10^6`
  (`BK = 32`) or `2.0·10^6` (`BK = 64`).

`Inst.ok`, for the instance:

- every problem meets `Gemm.ok`;
- `BM`, `BN`, `BK` are powers of two, with tiles of at most `2^20` elements (Triton's block
  limit);
- `NUM_SM ≥ 1`, `3G < 2^31` (`g * 3 + 2`), and `start G + NUM_SM < 2^31` (the global tile
  index `tile_idx += NUM_SM`);
- the metadata tensors have their sizes: `G` addresses each, `3G` sizes, `3G` leading
  dimensions;
- **no output aliasing**: each `C` is disjoint from every `A`, every `B`, the five metadata
  tensors, and the other problems' `C`. The inputs may overlap.

`Pre`, on the inputs:

- the metadata holds each problem's `M, N, K` and `lda, ldb, ldc` as `int32`, and its addresses
  as `int64`, as `group_gemm_fn` builds them;
- `A`, `B`, `C` are valid buffers;
- the entries of `A` and `B` are finite.

Any `G ≥ 0` is covered, and any sizes per problem, empty ones included (no tiles; `K = 0` gives
`C = 0`). Shapes are dynamic: nothing is fixed at compile time except the block sizes and
`NUM_SM`.

## Assumptions

- **`Compiler.Faithful`**: the library's compiler rule.
- **`Num.DotTotal`** for `cfg = {a := f16, b := f16, acc := f32}`: `tl.dot` has a result.
- **`Num.DotAcc`** for `cfg` with `rel(K) = (K + 2)·2^-22` and `abs(K) = (K + 2)·2^-126`.
  - The rule: every element of `tl.dot(a, b, acc)` over `K` products is finite and within
    `rel(K)·(|acc| + Σ|a·b|) + abs(K)` of `acc + Σ a·b`, when that fits `float32`.
  - Why these constants: the `float16` products are exact in `float32`. The constant charges
    each of the `K` addends and the accumulator `4u = 2^-22`. That is twice the `2^-23` of a
    truncating alignment (the tensor core's adder truncates, it does not round to nearest),
    plus two spare roundings.
  - The reviewer judges this constant against the target's `mma`/`wgmma` behaviour.

`consistent` shows that the three assumptions hold together. On `Platform.ref`, `tl.dot` is
one rounding of the exact result, which meets `DotAcc` because `rel(K) ≥ u` and
`abs(K) ≥ η` (`Platform.ref.dotAcc`).

## Proof

1. **One step of the `K` loop** (`safe_kstep`):
   - two full-tile loads (`safe_load_buf`): the pointers stay `A[row, s·BK + k]` and
     `B[s·BK + k, col]`;
   - `accumulator += tl.dot(a, b)` is `tl.dot_add`. Whichever form the device runs (the
     combined `tl.dot(a, b, acc)`, or `tl.dot` followed by a possibly fused addition),
     `DotLoop.dotAdd_step` bounds the step by `ρ·(|acc| + Σ|a·b|) + α`;
   - `DotLoop.accum_step` adds it to the running bound;
   - there is room in `float32`, since `|A|, |B| ≤ 65504` and `K < 2^31` give magnitudes below
     `2^66`.
2. **The `K` loop** (`safe_kloop`): `T = K/BK` steps from zero (`safe_forRange`).
3. **One tile** (`safe_tile`):
   - the metadata loads (`safe_load1`), `int64 → pointer` (`tl.intToPtr`), and the tile's
     coordinates (`//`, `%`: `safe_idiv1`, `safe_irem1`);
   - the `K` loop, the conversion to `float16` (`safe_cvt`), and the store (`safe_store_buf`).
     The tile's elements are distinct, and it writes only the tile.
4. **The schedule** (`safe_problem`, `safe_program`):
   - `ForInv` before problem `t`: `last_problem_end = start t`, and `tile_idx` is the program's
     first tile at or after `start t`, with `tile_idx < start t + NUM_SM`;
   - `WhileInv` inside the `while`: every tile of the program below
     `min(tile_idx, start (t+1))` is `Good`;
   - the variant is `start (t+1) + NUM_SM − tile_idx`;
   - stores of later tiles do not touch earlier ones (`cell_not_tile`).
5. **Footprints**:
   - program `p` reads the metadata and the `A`, `B` buffers, and writes the `C` cells of its
     tiles;
   - two cells sharing a byte are the same cell (`cell_unique`), so different programs write
     disjoint cells, and no program writes an input (`cell_not_input`).
6. **Claim**: `meets_independent`. `main` and `consistent` depend only on `propext`,
   `Classical.choice` and `Quot.sound`.

## Narrowings and modelling decisions

- **Full tiles** (`BM ∣ M`, `BN ∣ N`, `BK ∣ K`): required by the kernel itself.
- **Row-major `float16`** matrices with leading dimensions, as `group_gemm_fn` passes them.
- **`(K/BK)·ρ ≤ 1/2`**: under `DotAcc` the relative errors compound through the accumulator.
  Without a bound on `K`, the worst case could overflow `float32`.
- **Dropped hints**: `tl.multiple_of(a_ptrs, [16, 16])` and `tl.multiple_of(b_ptrs, [16, 16])`.
  - Both pointers are loop-carried (block arguments of the `scf.for` body). Triton stores the
    hint as `tt.divisibility_arg<N>` on the loop (`triton-3.8.0-ir.cc:411-424`), and no pass
    reads that attribute (`triton-3.8.0-AxisInfo.cpp:1248-1253, 1289-1291, 1333-1338`).
  - Taken literally, the hint would claim each element is 16-byte aligned, which is false. See
    the reviewer guide's no-op list.
- **`tl.cdiv`** is modelled as its definition `(x + (div − 1)) // div`
  (`triton-3.8.0-standard.py:34-43`), with `sdiv`.
