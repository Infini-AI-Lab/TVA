# Review of block_scaled_matmul_mxfp8, round 1, by r-mx8

## Verdict

accept
I found no blocking finding. The model follows the source line by line by SEMANTICS.md. Every name in it prints as a `TVA.*` operation or as the kernel's `cfgMx`. The drops (imports, the decorator, the compile-time `if` chains, the annotated `MIXED_PREC`) are sound for `output_type = 1` and `ELEM_PER_BYTE_A = ELEM_PER_BYTE_B = 1`. The scales' path (5-D `uint8` descriptors, blocks, offsets, reshape, `trans(0, 3, 2, 1, 4)`, reshape) gives each group of 32 elements the scale byte the host's reference gives it, which I checked on the CPU. The conditions cover the test and the benchmark's sizes, and every narrowing is stated. `Post` pins every element of `c` to the `float16` rounding of a `float32` value within an explicit tolerance of the exact scaled dot product, and keeps every other byte. That tolerance is about 0.5% of a typical output at `K = 2^14` and rejects the plausible wrong kernels. The three `[rule]` fields cite the library's facts for the model's `tl.dot_scaled` configuration and its launch. One non-blocking DOC finding: the README counts the benchmark's launches as covered, but the script makes them under proton's `hook="triton"`, which part (B), point 3 of `Compiler.Faithful`'s scope excludes.
